# Оценка качества вина

Веб-приложение для сервиса подписки: по 11 физико-химическим характеристикам и типу вина (красное или белое) оценивает, хорошее ли вино (экспертная оценка $\ge$ 7), и попадает ли оно в подборку при выбранном пороге.

## Запуск

Нужен **Python 3.12** (под него собран ноутбук `HW3_MMDA.ipynb`; и интерпретатор `.venv`, 3.12.3).

```bash
python3.12 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Откроется http://localhost:8501.

## Содержимое папки

- `app.py` - приложение.
- `model.joblib` - пайплайн `StandardScaler` $\to$ `LogisticRegression` (сохранён в `HW3_MMDA.ipynb`, в приложении только читается).
- `config.json` - порог по умолчанию (F1-оптимальный на валидации ≈ 0.263).
- `test.csv` - тестовая выборка для вкладки с метриками.
- `requirements.txt` - версии библиотек.

## Вкладки

- **Одно вино** - 12 слайдеров, вероятность хорошего вина и решение при текущем пороге.
- **Метрики модели** - матрица ошибок, precision, recall, F1, ROC-AUC,
  ROC и PR кривые с отмеченной точкой текущего порога.
- **Пакетное предсказание** - загрузка CSV, таблица с вероятностями и решениями, скачивание результата. При нехватке колонок выводится `st.error` со списком отсутствующих колонок.
- **Что выучила модель** - коэффициенты логистической регрессии после масштабирования.

## Кэширование (ответ на задание 4.5)

- Использование `@st.cache_resource` для загрузки модели: `cache_resource` отдаёт один и тот же объект всем вызовам и всем сессиям. Модели это подходит, она большая и в приложении никак не меняется. `@st.cache_data` отдаёт копию, из-за чего происходит большое количество лишних повторений.

- Использование `@st.cache_data` для загрузки таблиц: `cache_data` отдаёт **копию** результата, благодаря чему изменение результатов внутри одной вкладки, не влияет на другие вкладки.

- Использование без декораторов: в таком случае `app.py` перезапускался при каждом
  действии пользователя, отклик на них происходил бы с задержкой из-за большого количества действий, которые выполнялись при каждом перезапуске приложения.
